Хвост под контролем — ESP32-C3 Super Mini + SG90, тестовая прошивка 0.54

Это прошивка именно ESP32-C3 с 4 МБ flash, а не RP2040, ESP8266 или ESP32-S3.
Собрана Arduino-ESP32 3.3.3; USB CDC включён, flash DIO 40MHz.
Файл Hvost-SG90-0.54-ESP32C3.bin — полный образ, адрес записи 0x0.

ПОДКЛЮЧЕНИЕ (питание выключено при пайке)
1. SG90 красный -> стабилизированные +5 В.
2. SG90 коричневый -> GND источника; этот GND соединить с GND ESP32.
3. SG90 оранжевый/жёлтый -> GPIO4 (надпись 4 на плате).
4. ESP32 запитывать USB-C. Серво лучше запитать отдельной веткой того же источника 5 В.
Не подключать питание SG90 к 3V3. Не подавать +5 В на GPIO4.
Первый тест — без механической нагрузки. Физическое подёргивание дешёвой сервы при
подаче питания возможно независимо от программы. STOP снимает управляющие импульсы,
но не выключает питание сервы и не является механическим аварийным выключателем.

ПРОШИВКА С КОМПЬЮТЕРА
1. Отключить питание сервы, оставить только плату и USB-кабель с передачей данных.
2. В Chrome/Edge открыть официальный веб-прошивальщик:
   https://espressif.github.io/esptool-js/
3. Connect -> выбрать USB-порт ESP32 -> выбрать .bin и адрес 0x0 -> Program.
   Если подключения нет: удерживать BOOT, нажать/отпустить RESET, отпустить BOOT,
   повторить подключение. После записи нажать RESET.
4. Открыть последовательный монитор USB 115200 бод. Отправить INFO с переводом строки.
   Плата напечатает PAIRING PIN: XXXXXX. Это личный шестизначный PIN этой платы.
   Его не нужно присылать другим. PIN сохраняется при обычном выключении питания.
5. Закрыть монитор, отключить USB, подключить обычное питание и питание сервы.

Альтернатива веб-прошивке — установленный esptool:
  python -m esptool --chip esp32c3 --port COM5 --baud 460800 write-flash 0x0 Hvost-SG90-0.54-ESP32C3.bin
COM5 заменить своим портом. На Linux, например, /dev/ttyACM0.
Полная перепрошивка образа может стереть NVS, изменить PIN и сбросить сопряжение:
в этом случае удалить старое Hvost-SG90 в Bluetooth телефона и повторить сопряжение.

ПОДКЛЮЧЕНИЕ В ПРИЛОЖЕНИИ 0.54
В разделе Bluetooth найти Hvost-SG90, выбрать плату и подтвердить системное сопряжение,
ввести шестизначный PIN, прочитанный через USB. При включении платы, сопряжении,
обрыве и восстановлении связи программа сама не запускает поворот.
При потере Bluetooth управляющие импульсы снимаются.

ПРОВЕРКА ПО ПОРЯДКУ
1. Включить только плату: она появляется как Hvost-SG90.
2. Подключить серву и выполнить сопряжение: автоматического поворота быть не должно.
3. Нажать тест 90°, затем 60° и 120°. Между командами подождать минимум две секунды.
   Углы приблизительные: консервативные импульсы 1000..2000 мкс на условные 0..180°.
   Начальный тестовый диапазон ограничен 60..120°; расширения до упоров здесь нет.
4. Тестовый цикл TRIGGER: 90° -> через250мс120° -> через950мс90° -> через1650мс
   отключение импульсов. Новый запуск во время цикла игнорируется, не ставится в очередь.
5. Во время цикла нажать STOP: импульсы отключатся, возврат сам не запускается.
6. Выключить Bluetooth во время теста, затем включить: повторного запуска быть не должно.
7. Любая ручная команда угла автоматически перестаёт удерживать серву через2секунды.

Это позиционная SG90, не серва непрерывного вращения и не готовая лебёдка.
Движение реального механизма, усилие, направление и питание требуют отдельной проверки.
Физическая плата/серва у разработчика удалённо не подключены: выполнены компиляция и
программные тесты, аппаратная проверка остаётся на вашей плате.

BLE ПРОТОКОЛ (ASCII UTF-8, без обязательного перевода строки)
Имя: Hvost-SG90
Service: 1f90d7a0-7d43-4d6a-a7a8-0e5347433930
Command WRITE: 1f90d7a1-7d43-4d6a-a7a8-0e5347433930
Status READ/NOTIFY: 1f90d7a2-7d43-4d6a-a7a8-0e5347433930
Команды: PING, ANGLE:60 .. ANGLE:120, TRIGGER, STOP.
Ответы: READY:SG90:1, PAIRED, MOVING, RUNNING, DONE, STOPPED, BUSY, ERR:...
Запись требует BLE authenticated encryption MITM, bonding, Secure Connections.
Общего фиксированного пароля в прошивке нет. PIN создаётся случайно для устройства.

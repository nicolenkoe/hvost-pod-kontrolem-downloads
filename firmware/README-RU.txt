Хвост под контролем — ESP32-C3 Super Mini + SG90, тестовая прошивка 0.62

Это прошивка именно ESP32-C3 с 4 МБ flash, а не RP2040, ESP8266 или ESP32-S3.
Собрана Arduino-ESP32 3.3.3; USB CDC включён, flash DIO 40MHz.
Файл Hvost-SG90-0.62-ESP32C3.bin — полный образ, адрес записи 0x0.

ПОДКЛЮЧЕНИЕ (питание выключено при пайке)
1. Серва №1 (отдельный закрытый механизм звука): сигнал оранжевый/жёлтый -> GPIO4.
2. Серва №2 (механизм выдачи лакомства): сигнал оранжевый/жёлтый -> GPIO5.
3. Красные провода обеих SG90 -> внешний стабилизированный источник +5 В.
4. Коричневые провода обеих SG90 -> GND внешнего источника; этот GND соединить с GND ESP32.
5. ESP32 запитывать через USB-C. Сервы запитывать отдельными ветками внешних 5 В,
   а не через 3V3 платы. Источник должен выдерживать пиковый ток подключённых серв.
   Если у удлинителей другие цвета, проверить соответствие исходным проводам SG90.
Не подключать питание SG90 к 3V3. Не подавать +5 В на GPIO4 или GPIO5.
Первый тест обеих серв — без механической нагрузки. Механизм звука должен быть
полностью закрыт и недоступен животному; провода и движущиеся детали также недоступны.
Физическое подёргивание дешёвой сервы при
подаче питания возможно независимо от программы. STOP снимает управляющие импульсы,
но не выключает питание сервы и не является механическим аварийным выключателем.

ПРОШИВКА С КОМПЬЮТЕРА
1. Отключить питание обеих серв, оставить только плату и USB-кабель с передачей данных.
2. В Chrome/Edge открыть веб-прошивальщик Adafruit:
   https://adafruit.github.io/Adafruit_WebSerial_ESPTool/
3. Connect -> выбрать USB-порт ESP32 -> выбрать .bin и адрес 0x0 -> Program.
   Если подключения нет: удерживать BOOT, нажать/отпустить RESET, отпустить BOOT,
   повторить подключение. После записи нажать RESET.
4. После записи нажать RESET либо переподключить USB без BOOT.
5. PIN Bluetooth для ВСЕХ плат — 000000 (шесть нулей). Монитор порта не нужен.
6. В настройках Bluetooth телефона удалить прежнее сопряжение Hvost-SG90,
   затем найти плату в приложении и заново выполнить сопряжение с 000000.
7. Подключать питание серв после проверки платы, первый тест без нагрузки.

Альтернатива веб-прошивке — установленный esptool:
  python -m esptool --chip esp32c3 --port COM5 --baud 460800 write-flash 0x0 Hvost-SG90-0.62-ESP32C3.bin
COM5 заменить своим портом. На Linux, например, /dev/ttyACM0.
Полная перепрошивка образа может стереть NVS и сбросить сопряжение; PIN остаётся 000000:
в этом случае удалить старое Hvost-SG90 в Bluetooth телефона и повторить сопряжение.

ПОДКЛЮЧЕНИЕ В ПРИЛОЖЕНИИ 0.61
В разделе Bluetooth найти Hvost-SG90, выбрать плату и подтвердить системное сопряжение,
ввести 000000 — шесть нулей. При включении платы, сопряжении,
обрыве и восстановлении связи программа сама не запускает поворот.
При потере Bluetooth управляющие импульсы снимаются.

ПРОВЕРКА ПО ПОРЯДКУ
1. Включить только плату: она появляется как Hvost-SG90; выдаёт возможности RATTLE,TREAT.
2. Подключить сервы и выполнить сопряжение: автоматического поворота быть не должно.
3. Проверить отдельно «Погреметь цепочкой»: должна двигаться только серва №1 на GPIO4.
4. Проверить отдельно «Выдать лакомство»: должна двигаться только серва №2 на GPIO5.
   Прошивка поворачивает серву; фактическую выдачу и размер порции определяет ваш механизм.
5. Каждый цикл: 90° -> через 250 мс 120° -> через 950 мс 90° -> через 1650 мс
   отключение импульсов. Углы приблизительные: консервативные импульсы 1000..2000 мкс
   на условные 0..180°. Нельзя обещать точную физическую позицию без калибровки сервы.
6. Во время цикла нажать STOP: импульсы на ОБОИХ выходах отключатся, возврат сам не запускается.
7. Выключить Bluetooth во время теста, затем включить: повторного запуска быть не должно.
8. Старые тесты ANGLE:60, ANGLE:90, ANGLE:120 и TRIGGER управляют только GPIO4.
   Ручная команда угла автоматически перестаёт удерживать серву через две секунды.
9. Во время работы попытаться запустить другое действие: плата ответит BUSY, новое действие
   не выполнится позже само. Устройство выполняет только одно действие одновременно.
   Порядок нескольких действий, если их разрешает приложение, организует приложение.
10. Сначала проверить отдельные тесты и STOP, только затем включать действия в сценариях.

Это позиционная SG90, не серва непрерывного вращения и не готовая лебёдка.
Движение реального механизма, усилие, направление и питание требуют отдельной проверки.
Физическая плата/серва у разработчика удалённо не подключены: выполнены компиляция и
программные тесты, аппаратная проверка остаётся на вашей плате.

BLE ПРОТОКОЛ (ASCII UTF-8, без обязательного перевода строки)
Имя: Hvost-SG90
Service: 1f90d7a0-7d43-4d6a-a7a8-0e5347433930
Command WRITE: 1f90d7a1-7d43-4d6a-a7a8-0e5347433930
Status READ/NOTIFY: 1f90d7a2-7d43-4d6a-a7a8-0e5347433930
Команды: PING, ANGLE:60 .. ANGLE:120, TRIGGER, ACTION:RATTLE, ACTION:TREAT, STOP.
ACTION:RATTLE -> GPIO4; ACTION:TREAT -> GPIO5; TRIGGER и ANGLE всегда только GPIO4.
READ возвращает возможности: READY:HVOST:2:RATTLE,TREAT.
PING также публикует READY:HVOST:2:RATTLE,TREAT.
NOTIFY публикует статусы PAIRED, MOVING, RUNNING, DONE, STOPPED, BUSY, ERR:...
Для полной строки возможностей в уведомлении нужен ATT MTU не меньше 29;
альтернатива — защищённое READ характеристики, в том числе при стандартном MTU.
Подписка на NOTIFY — стандартный CCCD 0x2902, создаётся NimBLE автоматически.
Не отправлять ACTION:BOTH: такой команды нет.
Запись требует BLE authenticated encryption MITM, bonding, Secure Connections.
PIN общий фиксированный: 000000. Это выбранное владельцем упрощение подключения, не индивидуальный секрет устройства. Прошивка совместима с приложением 0.61; GPIO4/GPIO5 и команды не изменены.
